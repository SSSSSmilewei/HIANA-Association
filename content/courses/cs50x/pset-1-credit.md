# Credit

![Person holding credit cards](https://cs50.harvard.edu/x/psets/1/credit/credit_cards.jpeg)

## 要解决的问题

信用卡（或借记卡）当然是一种塑料卡片，你可以用它支付商品和服务的费用。卡片上印着一串数字，这串数字也存储在某个数据库里，这样当你的卡被用来买东西时，债权人就知道该向谁收款。世界上有很多人持有信用卡，所以这些数字相当长：American Express 使用 15 位数字，MasterCard 使用 16 位数字，Visa 使用 13 位和 16 位数字。而且这些都是十进制数字（0 到 9），不是二进制，这意味着，比如说，American Express 最多可以印出 10^15 = 1,000,000,000,000,000 张不同的卡！（那可是，呃，一千万亿。）

其实这有点夸张，因为信用卡号实际上是有一定结构的。所有 American Express 的卡号都以 34 或 37 开头；大多数 MasterCard 的卡号以 51、52、53、54 或 55 开头（它们也有一些其他可能的开头数字，但这道题我们不去考虑）；所有 Visa 的卡号都以 4 开头。但信用卡号里还内置了“校验和”（checksum），即至少一个数字与其他数字之间的某种数学关系。有了这个校验和，计算机（或者喜欢数学的人）无需查询数据库（可能很慢），就能检测出笔误（例如数字位置互换），即使检测不出伪造的卡号。当然，不诚实的数学家完全可以编造出一个同样满足该数学约束的假卡号，所以要做更严格的检查，仍然需要查询数据库。

在名为 `credit` 的文件夹中，创建名为 `credit.c` 的文件，用 C 语言实现一个程序，检查给定信用卡号的有效性。

## Luhn 算法

那么秘诀公式是什么呢？大多数卡使用的是 IBM 的 Hans Peter Luhn 发明的一种算法。根据 Luhn 算法，你可以这样判断一个信用卡号（在语法上）是否有效：

1. 从倒数第二位数字开始，每隔一位数字乘以 2，然后把这些乘积的各位数字相加。
2. 把这个和与那些没有乘以 2 的数字之和相加。
3. 如果总和的最后一位是 0（或者更正式地说，如果总和对 10 取模同余于 0），这个卡号就是有效的！

这有点绕，我们用 David 的 Visa 卡来试一个例子：4003600000000014。

1. 为便于讨论，我们先从倒数第二位数字开始，给每隔一位的数字加下划线：
   
   4003600000000014
   
   好，把每个带下划线的数字乘以 2：
   
   1•2 + 0•2 + 0•2 + 0•2 + 0•2 + 6•2 + 0•2 + 4•2
   
   得到：
   
   2 + 0 + 0 + 0 + 0 + 12 + 0 + 8
   
   现在把这些乘积的各位数字（而不是乘积本身）相加：
   
   2 + 0 + 0 + 0 + 0 + 1 + 2 + 0 + 8 = 13
2. 现在把这个和（13）与那些没有乘以 2 的数字之和（从末尾开始）相加：
   
   13 + 4 + 0 + 0 + 0 + 0 + 0 + 3 + 0 = 20
3. 没错，这个和（20）的最后一位是 0，所以 David 的卡是合法的！

所以，验证信用卡号并不难，只是手算起来有点繁琐。我们来写个程序吧。

## 实现细节

在 `credit` 目录下名为 `credit.c` 的文件中，编写一个程序：提示用户输入信用卡号，然后（通过 `printf`）报告它是否是有效的 American Express、MasterCard 或 Visa 卡号，依据的是本文中各自格式的定义。为了让我们可以自动化测试你的代码，我们要求你的程序输出的最后一行是 `AMEX\n`、`MASTERCARD\n`、`VISA\n` 或 `INVALID\n`，不多也不少。为简单起见，你可以假设用户的输入全是数字（也就是没有连字符，而实际卡片上可能会印有连字符），并且没有前导零。但不要假设用户的输入能放进一个 `int`！最好使用 CS50 库中的 `get_long` 来获取用户输入。（为什么？）

下面是你的程序在输入有效信用卡号（不带连字符）时应有的表现。

```
$ ./credit
Number: 4003600000000014
VISA
```

其实，`get_long` 本身就会拒绝连字符（以及更多内容）：

```
$ ./credit
Number: 4003-6000-0000-0014
Number: foo
Number: 4003600000000014
VISA
```

但是，要由你来识别那些不是信用卡号的输入（例如电话号码），即使它们全是数字：

```
$ ./credit
Number: 6176292929
INVALID
```

用大量输入测试你的程序，有效的和无效的都要试。（我们肯定会！）这里有 PayPal 推荐用于测试的[几个卡号](https://developer.paypal.com/api/nvp-soap/payflow/integration-guide/test-transactions/#standard-test-cards)。

如果你的程序在某些输入上表现不正确（或者根本无法编译），就该调试了！
